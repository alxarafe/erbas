# I18N-001 verification (Java)

## Scope and design

Spring MVC's AcceptHeaderLocaleResolver negotiates `en`/`es` per request, including
regional neutral-locale matching and quality preferences. English is explicit
base/default/fallback. Spring Boot MessageSource uses explicit namespaced basenames
with system-locale fallback disabled. Jakarta Validation comes from the first-party
spring-boot-starter-validation, with the existing Boot 4.1.1 parent controlling
versions. No independent validator or translation framework was introduced.

Core bundles live in `src/main/resources/i18n/core`. Future modules distribute
bundles under their own basename in their JAR; composition registers those
basenames explicitly. Domain/Application remain localization independent.
ValidationExceptionHandler converts only native request DTO validation failures
into Spring ProblemDetail, resolving MessageSourceResolvable errors recursively
and retaining canonical nested field/object paths. See [internationalization](../i18n.md).

Production shared v0.5.0 responses are unchanged. No human field is added to any
existing closed code-only error. The new DTO validation transport probes and their
bundles exist only in src/test; there is no new business or production probe API.
